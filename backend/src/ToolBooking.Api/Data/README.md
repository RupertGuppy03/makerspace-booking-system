# Data/

EF Core — database access against Supabase Postgres (Npgsql provider).

| File | Purpose |
|---|---|
| `AppDbContext.cs` | The DbContext: `DbSet<Tool>`, `DbSet<Reservation>`, `DbSet<User>` |
| `Migrations/` | Generated by EF Core — commit these, don't hand-edit |

## Migrations

```bash
dotnet ef migrations add <Name> --project src/ToolBooking.Api
dotnet ef database update --project src/ToolBooking.Api
```

## Rules

- Entity configuration (keys, relationships, column names) goes in `OnModelCreating` or an
  `IEntityTypeConfiguration<T>` class — not scattered as attributes on the models.
- Use `AsNoTracking()` for read-only queries.
- The connection string comes from configuration/`.env`, never hard-coded.

Our schema is also written by hand in `database/schema.sql` for Supabase. If you generate a
migration, mirror the change there so both stay true — decide as a team which one is the source of
truth before we get far.
